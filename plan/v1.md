# Kế Hoạch Tinh Chỉnh Backend Microservices (Retail Store) - v1.md

> **Phiên bản:** v1.0  
> **Ngày khởi tạo:** 2026-10-27  
> **Mục tiêu:** Chuyển đổi sample app `retail-store-sample-app` (AWS containers demo) thành một hệ thống backend microservices hoàn chỉnh, tinh gọn, ổn định cho mục đích triển khai và thực hành DevOps (CI/CD, Docker, Kubernetes, Monitoring, Chaos Engineering).

---

## 1. Định Hướng & Quyết Định Thiết Kế

1. **Phạm vi hệ thống:**
   - Tập trung vào **Backend Microservices**: Catalog (Go), Cart (Go), Orders (Go), Checkout (Python), Recommendations (Python).
   - Hạ tầng đi kèm cục bộ: MySQL, PostgreSQL, LocalStack (SQS emulator nếu cần worker mode).
2. **Quyết định đối với UI (`src/ui`):**
   - **GIỮ LẠI:** Theo yêu cầu của người dùng, service `src/ui/` (Java/Spring Boot) vẫn được bảo lưu nguyên vẹn để phục vụ test cục bộ hoặc chạy demo trực quan khi cần thiết.
   - **Tách biệt vận hành:** Cấu hình Docker Compose trong tương lai sẽ đưa UI vào một **Docker Compose profile riêng** (ví dụ `--profile full` hoặc `docker-compose.ui.yml`), giúp mặc định hệ thống chỉ khởi động backend thuần túy, tiết kiệm tài nguyên RAM/CPU.
3. **Quyết định đối với Load Generator (`src/load-generator`):**
   - **GIỮ LẠI:** Giữ lại kịch bản Artillery để hỗ trợ test tải, stress test trong các bài thực hành DevOps.
   - Sẽ cập nhật lại kịch bản để có thể bắn tải trực tiếp vào API Gateway / Backend endpoints khi không bật UI.
4. **Nguyên tắc thực thi:**
   - **Giai đoạn hiện tại (v1):** Chỉ dọn dẹp các tệp tin/thư mục rác upstream (fork artifacts), **tuyệt đối không sửa đổi logic code**.
   - Các giai đoạn kế tiếp (v2, v3,...) sẽ lần lượt xử lý cấu hình docker-compose, chuẩn hóa database, tối ưu image container và kịch bản CI/CD.

## 2. Danh Mục Các Service Cốt Lõi

| Service | Ngôn ngữ / Framework | Port | Persistence | Messaging | Trạng thái |
|---|---|---|---|---|---|
| **Catalog** | Go (Gin) | `8081` | MySQL (`catalogdb`) | — | Giữ nguyên, tinh chỉnh sau |
| **Cart** | Go (Gin) | `8082` | PostgreSQL (`retaildb`) | SQS (optional worker) | Giữ nguyên, sửa config sau |
| **Orders** | Go | `8083` | PostgreSQL (`retaildb`) | SQS (optional worker) | Giữ nguyên, sửa config sau |
| **Checkout** | Python (FastAPI) | `8085` | PostgreSQL (`retaildb`) | SQS (optional worker) | Giữ nguyên, sửa config sau |
| **Recommendations** | Python (FastAPI) | `8080` | MySQL (`catalogdb`) | — | Giữ nguyên |
| **UI** | Java 21 (Spring Boot) | `8080` (mapped `8888`) | — | — | **Giữ lại theo yêu cầu (chạy on-demand)** |
| **Load Generator** | Node.js (Artillery) | — | — | — | Giữ lại phục vụ DevOps testing |

## 3. Các Lỗi & Bất Cập Cấu Hình Đã Nhận Diện (Xử lý ở giai đoạn sau)

Cần ghi nhớ để sửa trong Phase 2, **chưa can thiệp ở v1**:
1. **`src/cart/docker-compose.yml`:** Khai báo DynamoDB (`RETAIL_CART_PERSISTENCE_PROVIDER=dynamodb`) trong khi code Go đã chuyển sang PostgreSQL.
2. **`src/orders/docker-compose.yml`:** Khai báo RabbitMQ trong khi code Go sử dụng SQS.
3. **`src/checkout/docker-compose.yml`:** Khai báo Redis (`RETAIL_CHECKOUT_PERSISTENCE_PROVIDER=redis`) trong khi code Python chỉ hỗ trợ PostgreSQL hoặc In-memory.
4. **Tham chiếu UI trong `src/app/docker-compose.yml`:** Có dòng include `src/ui/docker-compose.yml` nhưng file này không tồn tại trong thư mục UI.
5. **Database Connection:** Cần đồng nhất một cấu hình kết nối chuẩn vào PostgreSQL và MySQL dùng chung cho môi trường Docker Compose.
