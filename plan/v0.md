## 2. Phân Tích Chi Tiết Từng Service

### 2.1 UI (src/ui) — **THỪA HOÀN TOÀN**

**Đây là thứ cần bỏ đầu tiên.** UI là một Spring Boot + Spring Cloud Gateway + Thymeleaf app — đóng vai trò là:
- Frontend HTML (Thymeleaf templates)
- API Gateway (Spring Cloud Gateway) — reverse proxy sang các backend service
- Tích hợp Spring AI (Amazon Bedrock + OpenAI) cho chatbot demo

**Tại sao thừa:** Mục tiêu chỉ cần backend REST API. Các service backend (catalog, cart, checkout, orders) đã có OpenAPI spec riêng và expose port trực tiếp. UI chỉ là wrapper để người dùng dùng browser tương tác.

**Kéo theo những gì phức tạp:**
- `pom.xml` depend vào `spring-ai-starter-model-bedrock-converse`, `spring-ai-openai` → kéo thêm AI SDK
- `kiota-maven-plugin` → tự động generate client code từ OpenAPI spec của các service khác
- `spring-cloud-gateway-webflux` → phức tạp routing
- Dependency `microsoft-kiota-bundle` → gói Microsoft
- Build time rất lâu (Maven, Java 21, download nhiều dep)

### 2.2 Catalog (src/catalog) — **GIỮ, tinh chỉnh nhẹ**

**Ngôn ngữ:** Go, framework Gin  
**Persistence:** MySQL hoặc in-memory  
**API endpoints:**
- `GET /catalog/products` — danh sách sản phẩm
- `GET /catalog/products/:id` — chi tiết sản phẩm
- `GET /catalog/tags` — danh sách tags
- `GET /catalog/size` — số lượng sản phẩm
- `GET /catalog/search` — tìm kiếm
- `POST /catalog/reindex` — reindex OpenSearch

**Thứ cần xem xét bỏ:**
- **OpenSearch integration** (`repository/opensearch.go`) — phức tạp, không cần thiết cho DevOps lab. Catalog đã có in-memory search fallback và MySQL full-text không cần OpenSearch.
- **AWS X-Ray tracing** (`go.opentelemetry.io/contrib/propagators/aws/xray`) — AWS-specific, có thể bỏ nếu không dùng X-Ray
- **EC2 resource detector** (`go.opentelemetry.io/contrib/detectors/aws/ec2`) — AWS-specific

**Giữ lại:**
- Gin HTTP server
- Prometheus metrics (`/metrics`)
- Chaos controller (hữu ích cho DevOps demo)
- Health endpoint (`/health`)
- MySQL hoặc in-memory storage

---

### 2.3 Cart (src/cart) — **GIỮ, tinh chỉnh**

**Ngôn ngữ:** Go, framework Gin  
**Persistence:** PostgreSQL hoặc in-memory  
**Messaging:** AWS SQS (publish jobs)

**API endpoints cần thiết:**
- `GET /carts/:customerId`
- `DELETE /carts/:customerId`
- `GET /carts/:customerId/items`
- `POST /carts/:customerId/items`
- `PATCH /carts/:customerId/items`
- `GET /carts/:customerId/items/:itemId`
- `DELETE /carts/:customerId/items/:itemId`
- `GET /carts/:customerId/merge`

**Thứ cần xem xét bỏ hoặc làm rõ:**
- **`POST /jobs` endpoint + SQS Worker** — đây là feature SQS benchmark/demo, không phải core business logic. Nếu không cần demo SQS, có thể tắt (đặt `APP_MODE=api` để không chạy worker).
- Cart service trong `src/cart/docker-compose.yml` mặc định dùng **DynamoDB local** với `RETAIL_CART_PERSISTENCE_PROVIDER=dynamodb`, nhưng code `main.go` trong repo này đã rewrite sang **PostgreSQL** — có sự không nhất quán giữa docker-compose và code thực.

**Giữ lại:**
- Cart CRUD API
- PostgreSQL hoặc in-memory store
- Chaos middleware
- Health + Prometheus

---

### 2.4 Orders (src/orders) — **GIỮ, tinh chỉnh**

**Ngôn ngữ:** Go  
**Persistence:** PostgreSQL hoặc in-memory  
**Messaging:** SQS (worker mode)

**Thứ cần xem xét:**
- Worker mode (SQS consumer) có thể tắt bằng `APP_MODE=api` nếu không cần
- `src/orders/docker-compose.yml` định nghĩa **RabbitMQ** nhưng code Go dùng **SQS** → docker-compose cũ/lỗi thời, không khớp với code

**Giữ lại:** Orders CRUD API, PostgreSQL, health, metrics

---

### 2.5 Checkout (src/checkout) — **GIỮ, tinh chỉnh**

**Ngôn ngữ:** Python/FastAPI  
**Persistence:** PostgreSQL hoặc in-memory  
**Messaging:** SQS

**Thứ cần xem xét bỏ:**
- Worker mode (SQS) — có thể tắt bằng `APP_MODE=api`
- `src/checkout/docker-compose.yml` mặc định dùng **Redis** (`RETAIL_CHECKOUT_PERSISTENCE_PROVIDER=redis`) nhưng code Python **không có Redis implementation** — chỉ có in-memory và PostgreSQL. Docker-compose bị lỗi thời.

**Giữ lại:** Checkout REST API, PostgreSQL/in-memory, health, metrics

---

### 2.6 Recommendations (src/recommendations) — **OPTIONAL**

**Ngôn ngữ:** Python/FastAPI  
**Persistence:** MySQL hoặc in-memory  
**Vai trò:** Trả về gợi ý sản phẩm

Đây là service nhẹ nhất, dùng cùng MySQL với Catalog. Có thể giữ hoặc bỏ tùy nhu cầu demo.

### 2.7 Load Generator (src/load-generator) — **OPTIONAL, hữu ích**

Node.js + Artillery. Gửi traffic giả lập đến **UI** (target: `http://localhost:8888`). Nếu bỏ UI thì cần điều chỉnh scenario.yml để hit trực tiếp các backend endpoint.

## 3. Những Vấn Đề Không Nhất Quán (Bugs/Inconsistencies)

| Vị trí | Vấn đề |
|---|---|
| `src/cart/docker-compose.yml` | Cấu hình `RETAIL_CART_PERSISTENCE_PROVIDER=dynamodb` nhưng code main.go chỉ hỗ trợ `postgres` và `in-memory` |
| `src/orders/docker-compose.yml` | Khai báo RabbitMQ nhưng code Go dùng SQS — hoàn toàn khác nhau |
| `src/checkout/docker-compose.yml` | Khai báo Redis + `RETAIL_CHECKOUT_PERSISTENCE_PROVIDER=redis` nhưng Python code không có Redis repository |
| `src/app/docker-compose.yml` | Include `src/ui/docker-compose.yml` nhưng không tìm thấy file đó trong thư mục `src/ui/` |
| docker-compose.local.yml | Setup SQS queues cho cart, orders, checkout — nhưng chỉ catalog/cart worker thực sự cần (tùy mode) |

## 5. Phân Tích Infrastructure Dependencies

### Bức tranh thực tế của dependencies:

```
Catalog  ──→  MySQL (catalogdb)
Cart     ──→  PostgreSQL (retaildb)  ──→  SQS cart-queue (optional worker)
Orders   ──→  PostgreSQL (retaildb)  ──→  SQS orders-queue (optional worker)
Checkout ──→  PostgreSQL (retaildb)  ──→  SQS checkout-queue (optional worker)
Recommendations ──→ MySQL (catalogdb, shared với Catalog)
```

### Vấn đề quan trọng với docker-compose.local.yml:
File này setup PostgreSQL (một instance) với database `retaildb` cho cả Cart, Orders, Checkout cùng dùng. Thực tế trong docker-compose của từng service, họ dùng port 5432 khác nhau. Cần chuẩn hóa.

7. **Xóa `oss/`** (open-source compliance)
8. **Xem xét xóa `terraform/`** và `deploy/helm/` nếu deployment target là Docker Compose + plain K8s

### ✅ Nhóm 2 — Sửa các không nhất quán (ưu tiên cao)

9. **Sửa `src/cart/docker-compose.yml`** — đổi `dynamodb` → `postgres`, thêm depends_on postgres, bỏ carts-db DynamoDB
10. **Sửa `src/orders/docker-compose.yml`** — xóa RabbitMQ, thêm LocalStack SQS hoặc bỏ hẳn nếu chỉ dùng in-memory
11. **Sửa `src/checkout/docker-compose.yml`** — xóa Redis, đổi persistence sang `in-memory` hoặc `postgres`
12. **Kiểm tra và sửa `src/app/docker-compose.yml`** — file include `src/ui/docker-compose.yml` không tồn tại

### ✅ Nhóm 3 — Tạo docker-compose hợp nhất (ưu tiên cao)

13. **Viết một `docker-compose.yml` hợp nhất duy nhất** ở root level, bao gồm:
    - Tất cả backend service (catalog, cart, orders, checkout, recommendations)
    - Shared infrastructure (PostgreSQL, MySQL, LocalStack SQS)
    - Loại bỏ PgBouncer (phức tạp không cần cho lab)
    - Env vars nhất quán cho tất cả service
    - Healthcheck cho tất cả

### ✅ Nhóm 4 — Tinh chỉnh service (ưu tiên trung bình)

14. **Catalog — Bỏ hoặc tắt OpenSearch** bằng cách set `RETAIL_CATALOG_SEARCH_ENABLED=false` (đã là default), không cần xóa code
15. **Cart/Orders/Checkout — Quyết định dùng SQS hay không** — nếu không demo SQS, set `APP_MODE=api` để tắt worker
16. **Catalog/Orders Dockerfile** — đang dùng `public.ecr.aws/amazonlinux/amazonlinux:2023` → có thể đổi sang `golang:alpine` nhẹ hơn và không phụ thuộc ECR

### ✅ Nhóm 5 — Chuẩn hóa config (ưu tiên thấp)

17. **Tạo file `.env.example`** chứa tất cả env vars cần thiết cho mỗi service
18. **Cập nhật README.md** — ghi rõ đây là backend-only, bỏ references đến UI và AWS
19. **Xóa `nx.json` + `package.json` root** nếu không dùng Nx để build
